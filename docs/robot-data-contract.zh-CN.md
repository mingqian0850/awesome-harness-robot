# 从示教到执行：机器人数据接口

[首页](../README.md) · [English](robot-data-contract.en.md)

资料核对：2026-10-20；整理：2026-10-21。工程建议不代表已复现的实验。


## 三条记录分别保存

以下是建议的接口设计，不是某家工厂已公开的实现。

| 记录 | 关键内容 | 不能混淆的事实 |
| --- | --- | --- |
| 示教／策略轨迹 | 图像、状态、动作语义、时间戳、标定、任务和结果 | 人类参考、控制命令和执行反馈不同 |
| Harness 执行事件 | task_id、episode_id、工具请求、接收确认、超时、取消和恢复 | 请求成功送达不等于物理动作完成 |
| 工艺反馈 | part_id、设备状态、检验结果、返工和人工接管 | 完成取放不等于产品合格 |

用关联 ID 和明确的时钟约定连接三条记录；不要求所有传感器同频。每个观测记录采样时间，接收时间另存；记录插值、重采样和数据缺口。

## 超时后的恢复

物理动作通常不能像无副作用的查询一样盲目重试。若放置命令超时，先核对机器人、工件和工装状态，再决定继续、恢复或人工处理。软件请求去重不保证物理动作恰好执行一次。

保持模型建议、命令下发、控制器反馈和质量检查四个阶段可辨认。策略服务连接高频控制器时，由明确的接口处理动作过期、取消和接管；一段语言推理不能替代反馈记录。

## 实现参考与范围

[MCAP](https://mcap.dev/) 提供带时间戳的多通道日志容器，字段语义仍由应用定义。[龙旗](https://us.longcheer.com/en/col76/260.html) 披露机器人与测试设备通信及结果分流，未提供可直接复用的完整产线接口代码。

学习数据来源见[五类采集路线](https://github.com/mingqian0850/awesome_vla_deployment/blob/main/docs/zh/02-data-sources.md)。公开学习组件不能标成企业实际部署栈。

## 不训练练习

纸面写出一次“抓取成功、放置确认丢失”的事件序列，包含时间、关联 ID、状态来源和未知项。设计三种不同的恢复分支，并说明哪项新观测能够区分它们。不要执行真实机器人动作。
