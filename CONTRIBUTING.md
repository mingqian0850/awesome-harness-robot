# Contributing

Thanks for helping keep Awesome Harness Robot useful.

## Inclusion Criteria

A proposed entry should be directly relevant to robot agent harnesses, VLA systems, robot foundation/world models, their data, evaluation, simulation, safety, or deployment.

At least one of the following must be available:

- official runnable code;
- released weights or a documented public SDK;
- an accessible dataset with a usable schema;
- a benchmark with an evaluation protocol;
- a technically substantial system paper that changed implementation practice.

## Pull Request Checklist

- Add one item per pull request unless the entries are inseparable.
- Link to the official project, paper, or repository.
- Use the format `- Name — official URL — One factual sentence ending with a period.`, with the name linked in the actual entry.
- Explain the project's practical role; do not copy marketing text.
- State whether code, weights, data, or access are partial when that distinction matters.
- Put the item in the most specific section and preserve the section's rough chronological or conceptual order.
- Check that the URL works and does not require an unnecessary tracking redirect.
- Do not add star counts, benchmark superlatives without protocol context, referral links, or paywalled summaries when a primary source exists.

## Evidence and Safety

Prefer primary sources: official repositories, project pages, papers, model cards, dataset cards, and benchmark documentation.

Simulation scores, lab demonstrations, and vendor-reported results are not interchangeable. Phrase performance claims as results under the cited protocol. Inclusion is not an endorsement or safety certification.

## Updating or Removing Entries

Please open an issue or pull request when:

- a project changes name or canonical URL;
- code, weights, or datasets are released;
- a license or access condition changes;
- an implementation is archived or no longer reproducible;
- a description is inaccurate or overstates evidence.

## Style

- Use American English.
- Expand uncommon acronyms on first use.
- Keep descriptions concise.
- Avoid emoji inside list entries.
- Run a Markdown link checker when possible.
